# 06 逐層乒乓網格（`strategies.grid_pingpong:GridPingPongStrategy`）

## 來源

得獎帳戶的 TTB 買賣報告書顯示，主要獲利來自台積電期貨（CDF）的盤中掛單網格：

- 每個價位掛 1 口，成交後在高一格掛出。
- 同一價位一天可以來回十幾次。
- 約 70% 的來回賺 1 格，約 20% 打平。
- 大虧全部來自留倉和攤平。

本策略照這個行為實作，但只做當沖，收盤前一定平倉。

## 規則

- 錨點 `A` 對齊格距 `g`（`grid_points`）。空手時在 `A−g` 掛買、`A+g` 掛賣。
- 持有 `n` 層多單時，持倉一定是最靠近錨點的 `A−g … A−n·g`。原因是進場由上往下成交、出場由下往上成交。
- 因此每邊只需要一張單：
  - 最深一層的出場單，掛在 `A−n·g + exit_grids·g`。
  - 下一層的進場單，掛在 `A−(n+1)·g`。若已持有 `levels` 層，就不掛進場單。
  - 進場單價格若已經穿過市價（買單高於最新價或不低於賣價），這一輪先不掛，等價格回到該層再掛。這樣快速下跌時不會一路追買。
- 這剛好符合 gateway「每邊一張工作單」的限制。空單規則左右對稱。
- **停損**：價格超過最外層 `A−levels·g` 再 `stop_grids` 格時，送出 IOC 全平（`risk_exit`）。不論已持有幾層都會觸發，所以跳空越過停損線時不會先補滿所有層再停損。
  - 停損觸發後會持續平倉，直到部位歸零，期間不再進場。
  - 若只部分成交，不會把剩下的層重新掛回市價上方。
- **重錨**：空手時，價格離錨點達 `reanchor_grids` 格，就把錨點移到目前價格。
  - gateway 每 2 秒輪詢才把成交記進 ledger。第一層成交後、入帳前，策略可能還以為是空手而重錨。所以部位從 0 變成有部位時，一律用成交均價重建錨點，出場單才會在進場價高一格。
- **時段**：`first_entry_minute` 之後才進場，`last_entry_minute` 之後只出不進，`flatten_minute` 全平。engine 本身也會在收盤前 10 分鐘強制平倉。
- **重啟**：持有 `n` 層時，持倉均價在錨點下方 `(n+1)/2` 格。重啟後用這個關係從 ledger 均價推回錨點。

- **重錨距離**：`reanchor_grids` 必須在 0 到 1 之間。超過 1 格才重錨時，空手的第一層可能落在市價的另一邊。

`grid_points` 必須是 `tick_size` 的整數倍。股票期貨的跳動點依價格分段，所以 `tick_size` 要設成價格可能到達的最粗跳動點：CDF 設 5，CCF 設 0.5。

跳動點的依據是研究期間的 TAIFEX 逐筆成交資料：CDF 在 2,421～2,442 之間有 1 點的成交價差，2,500 以上只出現 5 點的倍數。2026/7/6 起股票期貨跳動點改制，各價格區間的跳動點請以期交所公告為準。CDF 價格在 2,500 附近來回，所以格距用 5 點，兩個區間都合法。

## 研究結果（2026-09-11～10-28，29 個交易日）

成本：手續費每口單邊 50 元，期交稅 0.00002。

回放方式：`replay_market_maker.replay`，用 independent 觸價成交模型，延遲 2.5 秒，逐日回放，每天收盤前平倉。

| 設定 | 日均淨損益 | 最差一天 | 獲利天數 | 每日送單（最多） | 保證金（13.5% 估） |
|---|---:|---:|---:|---:|---:|
| CCF 格 0.5、8 層、停損 3、重錨 1 | 108,127 | +11,550 | 29/29 | 662（1,528） | 約 31.5 萬 |
| CCF 同上，延遲 4.5 秒 | 91,326 | −5,615 | 28/29 | 622 | |
| CCF 同上，機率成交（觸價 35%） | 51,353 | −24,275 | 25/29 | 486 | |
| CDF 格 5、3 層、停損 3、重錨 1 | 132,549 | −245,521 | 22/29 | 93（309） | 約 201 萬 |
| CDF 格 5、3 層、停損 1（對照） | 127,836 | −225,816 | 21/29 | 106（309） | |
| CDF 停損 1，機率成交（觸價 35%） | 26,253 | −195,522 | 19/29 | 89 | |

- **CCF 是參數高原，不是單點最佳。** 層數 3～8、停損 2～5、重錨 1 或 3，共 24 組參數，日均都在 6.4 萬到 11 萬之間。不過停損只有 1 格、層數 2 時會虧錢，所以停損不能太緊。
- **CCF 的關鍵是 1 檔來回。** 格距改成 1 元（2 檔）時，日均只剩約 1.1 萬。
- **加大每層口數會虧錢。** 「見價見量」會用每筆成交量限制成交口數。震盪時的成交筆小，單子只成交一部分；順勢時的成交筆大，單子整筆吃滿。CCF 每層 5 口時日均約 −2.8 萬。要放大部位，應該做多個標的，不是加大單層口數。
- **其他候選標的。** 鴻海（DHF）和華邦電（FZF）格距 1 檔、8 層時，日均約 2 萬，可以當組合的一部分。合晶（PLF）、長榮（CZF）等在 repo 回放下接近打平或虧損，所以合約白名單只收 CDF、CCF、DHF、FZF。

## 尚未在 TTB 驗證

- 觸價即成交的規則。改成必須穿價時，CCF 和 CDF 的報酬都大幅下降。
- 股票期貨在 TTB 的代碼格式，預期是 `CCFK6`、`CDFK6`。
- 盤中保證金是否適用當沖減半。
- TTB 端是否有下單頻率限制。CCF 每分鐘最多約 52 張新單。

## 上線

範本：

- `automation/config.grid-ccf.example.json`
- `automation/config.grid-cdf.example.json`

切換方式：

```powershell
powershell -File automation\set_mode.ps1 -Mode ttb -Template config.grid-ccf.example.json
```

先 dry run 檢查輸出，確認後再加 `-Apply`。明確給 `-Template` 時，範本的商品和策略會蓋過目前設定。要從網格切回原本的組合策略，就明確指定預設範本：

```powershell
powershell -File automation\set_mode.ps1 -Mode ttb -Template config.competition.example.json
```

範本的 `liveGate.tickSize` 和 `liveGate.distanceTicks` 會讓探針單掛在市價下方約 5～6%，落在漲跌停範圍內。目前架構一個帳戶只能跑一隻 bot，啟動時要求整個帳戶沒有持倉和掛單，所以 CCF 和 CDF 不能同時跑。
